# Plan: Выжимка встречи через Claude Agent SDK

**PRD**: [docs/prd-meeting-summary-claude-agent.md](prd-meeting-summary-claude-agent.md)
**Дата**: 2026-08-22

## Фазы реализации

### Фаза 1: Краткое содержание встречи по кнопке

**Цель** Участник встречи нажимает кнопку, видит ход обработки и получает
краткое содержание встречи на её странице.

**Зависит от** ничего

**Затрагивает** database / backend / frontend

**Критерии PRD** 1, 2, 3, 4, 6, 8, 9, 10, 11, 12, 13

**Задачи**

- [x] Добавить таблицу выжимки встречи со статусом обработки, кодом причины
      ошибки, текстом краткого содержания.
- [x] Собирать вход для модели из всех файлов встречи категории `transcript`.
- [x] Отклонять вход длиннее предела отдельным кодом причины.
- [x] Получать краткое содержание от Claude Agent SDK структурированным
      ответом.
- [x] Отмечать ответ модели, который не разобрался, отдельным кодом причины.
- [x] Прерывать обработку по пределу времени с отдельным кодом причины.
- [x] Выполнять обработку фоном в процессе API, освобождая HTTP-запрос сразу.
- [x] Запускать обработку по `POST /meetings/:meetingId/summary`.
- [x] Отклонять запуск, пока прежняя задача встречи не завершилась.
- [x] Отклонять запуск для встречи без файлов категории `transcript`.
- [x] Заменять прежний результат при новом запуске.
- [x] Переводить в ошибку задачи, оставшиеся в обработке от прошлого запуска
      процесса API.
- [x] Отдавать статус, код причины ошибки, краткое содержание по
      `GET /meetings/:meetingId/summary`.
- [x] Отвечать `404 Meeting not found` постороннему пользователю на обоих
      маршрутах.
- [x] Показывать на странице встречи кнопку запуска, недоступную без
      транскриптов.
- [x] Обновлять статус обработки на открытой странице без перезагрузки
      браузером.
- [x] Показывать краткое содержание отдельным блоком после готовности.
- [x] Показывать причину упавшей обработки понятным пользователю текстом.
- [x] Перезапускать упавшую обработку кнопкой «Повторить».
- [x] Описать маршруты выжимки, её статусы, коды причин ошибок в
      `docs/api.md`.
- [x] Описать место выполнения обработки, жизненный цикл задачи в
      `docs/api-architecture.md`.

**Когда готова** Встреча с транскриптом по нажатию кнопки проходит путь от
очереди к готовому краткому содержанию без перезагрузки страницы, встреча без
транскриптов кнопку не даёт, упавшая обработка показывает причину и
перезапускается кнопкой, посторонний пользователь получает `404`, e2e-тест API
проходит на реальном вызове Claude Agent SDK и пропускает себя без ключа.

### Фаза 2: Задачи и решения встречи

**Цель** Вместе с кратким содержанием пользователь получает список задач с
ответственным из текста встречи и список принятых решений.

**Зависит от** Фаза 1

**Затрагивает** database / backend / frontend

**Критерии PRD** 4, 5, 6, 10, 13

**Задачи**

- [x] Добавить таблицы задач встречи, решений встречи, привязанные к выжимке.
- [x] Расширить запрос к модели списком задач с ответственным строкой.
- [x] Расширить запрос к модели списком принятых решений.
- [x] Сохранять задачи, решения одной транзакцией с кратким содержанием.
- [x] Удалять прежние задачи, решения при повторном запуске.
- [x] Отдавать задачи, решения в `GET /meetings/:meetingId/summary`.
- [x] Показывать задачи с ответственным отдельным блоком на странице встречи.
- [x] Показывать решения отдельным блоком на странице встречи.
- [x] Описать поля задач, решений, правило пустого ответственного в
      `docs/api.md`.

**Когда готова** Готовая выжимка показывает на странице встречи три блока,
задача без названного ответственного показывает его пустым, повторный запуск
заменяет оба списка целиком.

### Фаза 3: Ручное назначение ответственного

**Цель** Пользователь исправляет ответственного у задачи, выбирая участника
встречи.

**Зависит от** Фаза 2

**Затрагивает** backend / frontend

**Критерии PRD** 7, 11, 13

**Задачи**

- [ ] Отдавать участников встречи по `GET /meetings/:meetingId/participants` из
      контракта `user-identity.response.ts`.
- [ ] Назначать задаче ответственным участника встречи отдельным маршрутом.
- [ ] Снимать назначенного ответственного тем же маршрутом.
- [ ] Отдавать назначенного участника в задачах выжимки.
- [ ] Отвечать `404 Meeting not found` постороннему пользователю на обоих
      маршрутах.
- [ ] Показывать выбор участника в строке задачи на странице встречи.
- [ ] Показывать назначенного участника вместо имени из транскрипта.
- [ ] Описать маршрут участников, назначение ответственного, поля задачи в
      `docs/api.md`.

**Когда готова** Участник встречи назначает ответственным другого участника,
выбор виден после перезагрузки страницы, повторный запуск выжимки назначения
сбрасывает, посторонний пользователь получает `404`.
