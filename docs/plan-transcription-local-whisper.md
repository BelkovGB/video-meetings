# Plan: Транскрибация записей встречи локальным Whisper

**PRD**: [docs/prd-transcription-local-whisper.md](prd-transcription-local-whisper.md)
**Дата**: 2026-08-21

Фаза 1 реализована и ждёт коммита: миграция, `apps/api/src/transcription/**`,
воркер и оба e2e-спека лежат в рабочем дереве.

## Фазы реализации

### Фаза 1: Очередь транскрибации и воркер

**Цель** Загруженная запись без участия пользователя превращается в файл
транскрипта с таймкодами и появляется в списке файлов встречи.

**Зависит от** ничего

**Затрагивает** database / backend

**Критерии PRD** 1, 4, 14, 15

**Задачи**

- [ ] Добавить таблицу задачи транскрибации со статусами, арендой воркера,
      счётчиком попыток.
- [ ] Создавать задачу при успешной загрузке файла категории `audio` либо
      `video`.
- [ ] Захватывать задачу воркером атомарно, по одной за раз.
- [ ] Приводить исходную запись к 16 кГц моно через ffmpeg перед
      распознаванием.
- [ ] Сохранять результат файлом категории `transcript` мимо лимита активных
      загрузок, с учётом резерва свободного места.
- [ ] Удалять транскрипт с задачей вместе с исходной записью.

**Когда готова** Загруженный mp3 появляется в списке файлов встречи как
транскрипт с таймкодами, загрузка pdf задачу не создаёт, две записи подряд
выполняются по очереди, удаление записи не оставляет файлов в хранилище.

### Фаза 2: Статус расшифровки, ошибка, повтор

**Цель** Пользователь видит ход расшифровки на странице встречи и перезапускает
упавшую запись, не перезагружая браузер.

**Зависит от** Фаза 1

**Затрагивает** backend / frontend

**Критерии PRD** 2, 3, 11, 12, 13, 16

**Задачи**

- [ ] Отдавать статус расшифровки записи в списке файлов встречи.
- [ ] Отдавать машинный код причины ошибки в статусе, без путей хранения.
- [ ] Возвращать задачу в очередь по запросу повтора от владельца либо
      участника.
- [ ] Возвращать в очередь задачу, потерявшую аренду воркера, по пределу
      времени выполнения.
- [ ] Показывать четыре статуса расшифровки в строке записи на странице
      встречи.
- [ ] Обновлять статус на открытой странице, пока у встречи есть незавершённые
      задачи.
- [ ] Показывать причину ошибки рядом с кнопкой повтора в строке упавшей
      записи.
- [ ] Описать статусы расшифровки, повтор задачи, жизненный цикл воркера в
      документации API.

**Когда готова** Открытая страница встречи показывает переход записи из очереди
в обработку и в готовность без перезагрузки браузером, упавшая запись
возвращается в очередь по кнопке повтора, задача остановленного воркера
возвращается в очередь без ручного вмешательства.

### Фаза 3: Говорящие в транскрипте

**Цель** Реплики транскрипта помечены голосами, API отдаёт список говорящих
записи.

**Зависит от** Фаза 2

**Затрагивает** backend

**Критерии PRD** 5, 6, 7, 11, 16

**Задачи**

- [ ] Подключить модель диаризации к воркеру с токеном доступа из конфигурации.
- [ ] Определять число говорящих автоматически при распознавании.
- [ ] Хранить говорящих записи с меткой «Участник N», суммарной длительностью
      речи, таймкодом первой реплики.
- [ ] Удалять говорящих вместе с исходной записью.
- [ ] Ставить метку говорящего рядом с таймкодом в каждой реплике транскрипта.
- [ ] Отдавать список говорящих исходной записи по политике
      owner-or-participant.
- [ ] Описать говорящих записи в `docs/api.md`.

**Когда готова** На фикстуре с двумя голосами API возвращает двух говорящих с
длительностью речи и таймкодом первой реплики, а скачанный транскрипт помечает
реплики «Участник 1», «Участник 2».

### Фаза 4: Связывание говорящих с участниками

**Цель** Пользователь назначает участников встречи голосам записи, и их имена
попадают в скачиваемый транскрипт.

**Зависит от** Фаза 3

**Затрагивает** backend / frontend

**Критерии PRD** 8, 9, 10, 11, 16

**Задачи**

- [ ] Отдавать состав участников встречи с непрозрачным handle, отображаемым
      именем, версией аватара.
- [ ] Сохранять связь говорящего с участником встречи.
- [ ] Обновлять связь повторным вызовом, включая снятие пустым значением.
- [ ] Отклонять указание пользователя не из этой встречи, не раскрывая его
      существования.
- [ ] Подставлять отображаемое имя участника вместо «Участник N» в скачиваемый
      транскрипт.
- [ ] Показывать список говорящих записи с длительностью речи, таймкодом первой
      реплики.
- [ ] Выбирать участника встречи для говорящего в интерфейсе.
- [ ] Показывать последнее сохранённое состояние связи после смены, после
      снятия.
- [ ] Описать состав встречи, связывание говорящих в `docs/api.md`.

**Когда готова** Пользователь связывает «Участника 1» с человеком из состава
встречи, меняет связь, снимает её, и скачанный после этого транскрипт содержит
назначенное имя, а попытка связать постороннего отклоняется тем же ответом, что
обращение к чужой встрече.
