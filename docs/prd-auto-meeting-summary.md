# PRD: Автоматическая выжимка встречи

**Дата**: 2026-08-23
**Статус**: Draft

## Цель

Участник встречи получает выжимку — краткое содержание, задачи и
договорённости — без нажатия кнопки: она появляется, как только готова
расшифровка, и пересчитывается, когда к встрече добавили новую.

## Пользовательские сценарии

- Загружает запись встречи -> бот делает расшифровку -> выжимка появляется на
  странице встречи сама.
- Загружает готовый текст расшифровки -> выжимка появляется сама.
- Загружает второй файл, пока первый распознаётся -> загрузка проходит, выжимка
  ждёт конца обработки.
- Смотрит страницу, пока идёт загрузка или распознавание -> видит «ждём
  расшифровку», выжимка не стартует, даже если готовая расшифровка уже есть.
- Добавляет новую расшифровку к встрече с готовой выжимкой -> выжимка
  пересчитывается, прежние задачи и договорённости заменяются новыми.
- Видит упавшую выжимку -> читает причину и нажимает «Повторить».
- Хочет пересчитать выжимку сам -> нажимает «Обновить выжимку» в любой момент.

## Не в скоупе

- Файлы категорий, кроме расшифровки: pdf, docx и прочие документы в выжимку не
  попадают.
- Ручное назначение ответственного у задачи — фаза 3 плана
  `docs/plan-meeting-summary-claude-agent.md` отменена.
- Тесты экрана Playwright (`npm run test:e2e:web`) отключены до работ по
  дизайну, панель проверяется вручную.
- Работа нескольких процессов API одновременно.

## Технические ограничения

- Распознавание идёт в отдельном процессе-воркере, выжимка — в процессе API;
  общаются они только через базу.
- Активные загрузки видны лишь в памяти процесса API, поэтому проверка «на
  встречу идёт загрузка» верна для одного процесса API.
- Вход модели — файлы категории `TRANSCRIPT` в статусе `READY`, как описано в
  `docs/api.md`, раздел `## Meeting summary`.
- Пределы `SUMMARY_MAX_INPUT_CHARS` и `SUMMARY_TIMEOUT_MS` и коды отказов
  `INPUT_TOO_LARGE`, `MODEL_OUTPUT_INVALID`, `TIME_LIMIT_EXCEEDED`,
  `INTERRUPTED`, `INTERNAL_ERROR` остаются прежними.
- Повторный запуск заменяет краткое содержание, задачи и договорённости
  целиком — так уже устроен ручной перезапуск.
- Каждый прогон стоит денег, поэтому лишние запуски считаются дефектом.

## Критерии готовности

1. Встреча с готовой расшифровкой и без выжимки получает выжимку без действий
   пользователя.
2. Пока у встречи есть задание распознавания в очереди или в работе, выжимка не
   стартует.
3. Пока на встречу идёт загрузка файла, выжимка не стартует.
4. Новая готовая расшифровка у встречи с завершённой выжимкой запускает
   пересчёт.
5. Пересчёт заменяет краткое содержание, задачи и договорённости целиком.
6. Упавшая выжимка сама не перезапускается, пока не появится новая расшифровка
   или пользователь не нажмёт кнопку.
7. Загрузка нового файла доступна во время распознавания и во время выжимки.
8. Кнопка ручного запуска остаётся: «Обновить выжимку», при ошибке —
   «Повторить».
9. Панель показывает «ждём расшифровку», пока у встречи нет готовой расшифровки
   или распознавание ещё идёт.
10. Открытая страница показывает появление и смену состояния выжимки без
    перезагрузки браузером.
11. Автозапуск и его условия описаны в `docs/api.md`, планировщик и жизненный
    цикл задачи — в `docs/api-architecture.md`.
12. E2E-тест API подтверждает критерии 1, 2, 4 на реальном вызове модели.
