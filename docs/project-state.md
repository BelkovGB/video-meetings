# Состояние проекта: мягкий архив

**Дата**: 2026-08-25
**Ветка**: `master`

Проект уходит в паузу. Этот файл — точка возврата: что уже работает, как это
поднять, чем проверять и что осталось. Он описывает состояние на дату выше;

## Что это за продукт

Участник загружает запись встречи. Отдельный процесс-воркер превращает её в
расшифровку. По готовой расшифровке модель Claude сама собирает выжимку:
краткое содержание, задачи и договорённости. Задачи доступны наружу по
протоколу MCP, так что их можно читать и править из редактора или агента.

Проект тренировочный: главная цель — отладить процесс разработки с агентами,
а не сам продукт. Отсюда правило, которым стоит мерить любое предложение:
если решение улучшает продукт, но удлиняет цикл разработки, выбирается более
короткий цикл.

## Как поднять локально

1. `npm install` в корне.
2. `.env` в корне — из `.env.example`: `DATABASE_URL`, `JWT_SECRET`,
   `WEB_ORIGIN`, `NEXT_PUBLIC_API_URL`, настройки распознавания.
3. `apps/api/.env` — `ANTHROPIC_API_KEY` от Claude Console. Без него выжимка
   падает, а её тесты пропускают себя, объявляя об этом.
4. Запустить Docker Desktop, затем базу и миграции:

```bash
npm run db:up
```

```bash
npm run db:migrate
```

5. Приложение: `npm run dev` — веб на http://localhost:3000, API на
   http://localhost:3001.
6. Расшифровка идёт отдельным процессом, `npm run dev` его не поднимает
   (issue #126):

```bash
npm run worker
```

Распознаванию нужны `ffmpeg` и внешняя команда в `TRANSCRIPTION_COMMAND` —
переменные перечислены в [docs/api.md](api.md), раздел
`## Transcription worker configuration`.

## Чем проверять

```bash
npm run format:check && npm run lint && npm run build
```

```bash
npm run test:ralph
```

```bash
npm run test:e2e:api
```

Про эти команды важно знать три вещи.

`test:e2e:api` ходит в реальный Anthropic API — набор `claude-agent` и
`meeting-summary` делают настоящие вызовы модели, поэтому прогон стоит денег
(центы на `claude-haiku-4-5`) и занимает минуты. Он же требует поднятой базы.
Тот же набор запускает pre-commit хук, поэтому коммит без базы не пройдёт.

`test:e2e:web` (Playwright) намеренно выключен из набора проверок Ralph ради
скорости прогонов. Вернуть — это одна строка `"test:e2e:web"` в
`validationScripts` файла `.agents/ralph.config.json`. Пока он выключен,
изменения экрана проверяются руками.

Визуальные эталоны снимает только оператор, командой
`npm run test:e2e:web:visual`; инвентарь — `apps/web/e2e/visual-baselines.json`.
Сессия агента эталоны не рисует: снимок действителен лишь в среде, где снят.
Сейчас три имени `avatar-preview-panel-*` числятся в `pending` и ждут пересъёмки.

## Как здесь ведётся разработка

Порядок один и тот же: PRD (скилл `prd`) → план фаз (`plan_phase`) → задачи в
GitHub (`issues`) → прогон Ralph по milestone. Реализация начинается с задачи,
а не с кода: одобренный план сам по себе не команда писать код.

Правила для агентов лежат в `AGENTS.md` в корне и рядом с каждым приложением;
`CLAUDE.md` подключает их же. Конфиг прогонов `.agents/ralph.config.json` —
территория оператора: пороги, фазы и набор проверок задаёт человек.

Замечания ревью, не дотянувшие до порога критичности, всегда уходят в GitHub
как issue, а не теряются: беклог ниже разбирается вручную.

Кроме беклога, стоит помнить о трёх вещах:

1. Дизайн-система доведена только до дашборда; страница встречи и профиль живут

   отладочное удобство для подключения MCP-клиентов, и его надо убрать раньше,
   чем проект окажется где-то кроме локальной машины.

## С чего начинать в следующий раз

1. Поднять окружение по шагам выше и прогнать проверки — они должны быть
   зелёными на чистом `master`.
2. Прочитать [docs/api.md](api.md) и [docs/api-architecture.md](api-architecture.md):
   контракт и устройство описаны там, а не здесь.
3. Разобрать беклог вместе с оператором и решить, что из него ещё нужно бизнесу.
4. Новую бизнес-задачу оформить как PRD → план фаз → issues и только потом
   отдавать в работу.
5. Если работа снова касается экранов — сначала вернуть `test:e2e:web` в набор
   проверок и переснять эталоны, иначе фронт проверять нечем.
