# PRD: Выжимка встречи через Claude Agent SDK

**Дата**: 2026-08-22
**Статус**: Draft

## Цель

Участник встречи нажимает одну кнопку и вместо чтения транскрипта получает
краткое содержание встречи, список задач с ответственными и список принятых
решений.

## Пользовательские сценарии

- Открывает встречу, у которой есть хотя бы один транскрипт -> видит кнопку
  «Сделать выжимку».
- Нажимает кнопку -> видит статус обработки и его смену без перезагрузки
  страницы.
- Дожидается готовности -> на странице встречи появляются три блока: краткое
  содержание, задачи и решения.
- Смотрит задачу -> видит формулировку и ответственного так, как его назвали на
  встрече; если не назвали — ответственный пуст.
- Ответственный назван неточно или не назван -> вручную выбирает участника
  встречи, выбор сохраняется и виден после перезагрузки.
- Обработка упала -> видит статус ошибки с причиной и кнопку «Повторить»;
  повтор запускает обработку заново.
- Загрузил вторую запись и дождался её транскрипта -> нажимает кнопку снова и
  получает выжимку по всем транскриптам встречи вместо прежней.
- Открывает встречу без транскриптов -> кнопка недоступна и объясняет, почему.
- Не участвует во встрече -> не видит ни кнопки, ни выжимки: встреча для него не
  существует.

## Не в скоупе

- Автоматический запуск обработки после транскрибации: запуск только по кнопке.
- Пометка «выжимка устарела» и автоматический пересчёт при появлении нового
  транскрипта.
- Редактирование текста выжимки, формулировок задач и решений; добавление и
  удаление задач вручную. Руками меняется только ответственный.
- История версий: новая выжимка заменяет прежнюю без возможности вернуться.
- Сроки задач, отметка выполнения, экспорт в трекер, уведомления ответственным.
- Отдельная выжимка по одной записи, а не по встрече.
- Разделение говорящих: ответственный берётся из текста реплик, а не из голоса.
- Выбор модели, промпта и языка ответа пользователем.
- Массовый прогон встреч, транскрипты которых появились до этой фичи.

## Технические ограничения

- `ClaudeAgentModule` уже написан (`apps/api/src/claude-agent`): ключ
  `ANTHROPIC_API_KEY` из `apps/api/.env`, модель `claude-haiku-4-5`, один ход,
  без инструментов и без чтения настроек с диска. `AppModule` его пока не
  импортирует, единственный вызывающий — `apps/api/test/claude-agent.e2e-spec.ts`.
- Вызов идёт в реальный Anthropic API и списывает деньги со счёта. Тест обязан
  пропускать себя, когда ключ не настроен, как это уже делает
  `claude-agent.e2e-spec.ts`.
- SDK запускает Claude Code дочерним процессом. Дочерний процесс не наследует
  `process.env` и логин Claude Code того, кто запустил API: иначе он отвечает от
  имени разработчика и тест зеленеет с любым ключом. Правило зафиксировано в
  `claude-agent.service.ts`, новый вызывающий его не обходит.
- Обработка занимает десятки секунд и дольше. HTTP-процесс не может держать
  запрос всё это время, поэтому состояние задачи хранится в базе, а клиент
  опрашивает статус — как уже сделано для транскрибации.
- Модель возвращает текст. Перед записью в базу ответ нужно проверить на
  соответствие ожидаемой структуре; неразобранный ответ — отдельный код ошибки,
  как `RECOGNITION_OUTPUT_INVALID` у транскрибации.
- Транскрипт может не поместиться в контекст модели: предел размера файла — 1 ГиБ,
  а запись длится часы. Нужны предел длины входа и предел времени выполнения
  задачи, каждый со своим кодом ошибки.
- Источник — все файлы встречи категории `transcript`, включая загруженные
  пользователем `.txt`, `.vtt` и `.srt`: валидатор даёт им ту же категорию, что и
  результату воркера транскрибации.
- Выжимка содержит содержимое встречи и подчиняется той же политике
  owner-or-participant, что остальные данные встречи.
- Ответственного выбирают из участников встречи, а API сейчас не отдаёт их
  список. Поля чужого пользователя, которые видно другому, задаёт
  `apps/api/src/users/models/user-identity.response.ts`; новый список строится
  из него и не расширяет контракт.
- Транскрипт лежит в `UPLOAD_DIR` под случайным ключом. Ключи хранения,
  внутренние идентификаторы и пути не попадают ни в ответы новых маршрутов, ни в
  тексты ошибок.
- Выжимка принадлежит встрече, а не файлу: удаление записи и её транскрипта не
  удаляет уже полученный результат.

## Критерии готовности

1. У встречи хотя бы с одним файлом категории `transcript` кнопка запуска
   доступна; без транскриптов она недоступна и объясняет причину.
2. Нажатие кнопки создаёт задачу и возвращает ответ, не дожидаясь модели.
   Повторное нажатие, пока задача не завершилась, второй задачи не создаёт.
3. Страница встречи показывает статусы «в очереди», «обрабатывается», «готово» и
   «ошибка» и меняет их без перезагрузки браузером; поведение покрыто e2e-тестом
   веба.
4. Успешная задача сохраняет в базе краткое содержание встречи, список задач и
   список решений, привязанные к встрече.
5. У задачи хранится ответственный строкой в том виде, в каком его назвали на
   встрече, либо пустое значение, если не назвали.
6. Страница встречи показывает краткое содержание, задачи с ответственными и
   решения тремя отдельными блоками после готовности.
7. Участник встречи назначает задаче ответственным участника этой встречи;
   выбор сохраняется и виден после перезагрузки страницы.
8. Ответ модели, который не разобрался в ожидаемую структуру, превышение предела
   длины входа и превышение предела времени переводят задачу в ошибку, каждый со
   своим машинным кодом причины; ни один код не содержит путей и ключей
   хранения.
9. Кнопка «Повторить» на упавшей задаче запускает обработку заново.
10. Запуск при уже готовой выжимке заменяет её результат целиком, включая
    вручную назначенных ответственных.
11. Пользователь вне встречи получает `404 Meeting not found` на запуске,
    статусе, чтении выжимки и назначении ответственного.
12. e2e-тест API проходит на реальном вызове Claude Agent SDK, а без
    настроенного ключа пропускает себя.
13. `docs/api.md` описывает новые маршруты, поля выжимки и коды ошибок;
    `docs/api-architecture.md` — где выполняется обработка и жизненный цикл
    задачи.
