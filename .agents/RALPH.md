# Ralph Loop для Codex

Codex не использует Claude Code `Stop` hook. В этом проекте
циклом управляет внешний Node.js-скрипт `.agents/ralph-loop.mjs`.
Правила автономной сессии хранятся отдельно в `.agents/ralph-rules.md` и
добавляются в prompt только при запуске Ralph Loop.

## Перед запуском

1. В `.agents/ralph.config.json` указать **точное** название GitHub milestone.
2. Указать целевую ветку в поле `branch`.
3. Убедиться, что рабочее дерево чистое.
4. Проверить авторизацию `gh auth status` и `codex --version`.

В режимах `--once` и `--run` скрипт сам перейдёт на ветку `branch`. Если её нет
локально, он подключит удалённую ветку или создаст новую от `origin/baseBranch`.
При грязном рабочем дереве это запрещено. `--check` ничего не переключает и не
создаёт.

## Что происходит в одной итерации

1. Скрипт получает title, body и URL следующей issue.
2. В prompt подставляются issue, branch, milestone, лимит попыток и
   содержимое `.agents/ralph-rules.md`.
3. Оркестратор считает уникальные `item.started`/`item.completed` из `codex exec --json`.
   Служебные items типа `error` не учитываются. При попытке начать шаг после
   `maxTurns` дочерний процесс Codex принудительно завершается.
4. Codex на модели из `developmentModel` (`gpt-5.6-terra`) работает в sandbox
   `workspace-write`: реализует задачу по TDD, запускает проверки и делает
   self-review, но не имеет права изменять `.git` или GitHub.
5. Скрипт проверяет ветку и изменения, повторно запускает обязательные проверки и
   создаёт ровно один commit.
6. Отдельный read-only `codex exec` на модели `review.model`
   (`gpt-5.6-terra`) проверяет созданный commit и пишет
   структурированный результат в `.agents/last-review.json`.
7. Только после успешного review оркестратор закрывает issue через GitHub CLI.
8. При замечаниях review issue остаётся открытой, в неё добавляется комментарий,
   и `--run` передаёт её Terra на следующей итерации. Техническая ошибка review
   останавливает цикл, потому что результат нельзя считать проверенным.

## Что происходит после завершения milestone

1. Когда открытых issues больше нет, скрипт выполняет финальные npm-проверки,
   отправляет ветку и создаёт draft PR (либо находит уже открытый PR этой ветки).
2. Модель из `milestoneReview.model` (`gpt-5.6-sol`) проверяет весь diff ветки
   относительно `baseBranch`, а не отдельный commit.
3. В review учитываются архитектура, взаимодействие изменений из разных issues,
   безопасность, производительность, масштабирование, тесты и соответствие PRD.
4. Sol возвращает структурированный JSON в
   `.agents/last-milestone-review.json`; только оркестратор публикует его в PR
   через GitHub CLI.
5. При FAIL оркестратор создаёт по одной issue на каждый finding в текущем
   milestone. Повторный finding не создаёт дубликат: существующая открытая issue
   используется снова, а закрытая переоткрывается.
6. Terra последовательно исправляет review-issues, после чего ветка отправляется
   заново и Sol проверяет новый SHA. Цикл продолжается до PASS либо до достижения
   `maxIterations`/`maxTurns`.
7. PR остаётся draft даже при PASS: окончательное решение о merge принимает
   человек.
8. Повторный `--run` не расходует токены на уже опубликованный PASS того же SHA:
   скрипт ищет в PR
   скрытый маркер с моделью и SHA. После нового commit SHA изменится, и Sol
   выполнит review заново.

## Команды

```powershell
# Только проверить конфиг, GitHub, milestone и ветку
node .agents/ralph-loop.mjs --check

# Выполнить ровно одну issue и остановиться
node .agents/ralph-loop.mjs --once

# Выполнить issues, создать draft PR и запустить итоговый Sol-review
node .agents/ralph-loop.mjs --run
```

Для первого тренировочного запуска использовать `--once` и вручную проверить
изменения и commit.

## Защита от ошибок

Скрипт останавливается, если:

- не заполнены `milestone`, `branch` или `prompt`;
- текущая Git-ветка не совпадает с конфигом;
- перед `--once` или `--run` есть незакоммиченная работа;
- Codex не оставил изменений для commit;
- Codex попытался превысить `maxTurns`;
- Codex сменил ветку, самостоятельно создал commit или изменил issue;
- оркестратор не смог создать ровно один commit или очистить рабочее дерево;
- независимый review не завершился по технической причине;
- milestone-review вернул FAIL без структурированных findings;
- достигнут `maxIterations`;
- GitHub, Git или Codex вернули ошибку.

Перед push и PR выполняются npm scripts из `validationScripts`. По умолчанию это
`format:check`, `lint` и `build`. Если хотя бы одна проверка не прошла, PR не создаётся.

`--run` создаёт draft PR по умолчанию. Для обычного PR укажите
`"draftPullRequest": false`.

Лимит исправлений красных тестов задаётся полем `maxTestFixAttempts`. По
умолчанию это 5. После лимита Codex должен оставить диагностику в финальном
сообщении; issue остаётся открытой.

`maxTurns` применяется отдельно к сессии реализации и локальному review issue.
Для итогового review используется `milestoneReview.maxTurns`. `maxIterations`
ограничивает суммарное количество обычных и автоматически созданных review-issues,
обрабатываемых за один `--run`. Это защита от роста контекста и бесконечного
fix-review цикла, но не замена timeout: один зависший внешний процесс может не
создавать новых шагов.

> Временные результаты review внутри `.agents/` игнорируются. Конфигурация,
> правила, документация и скрипт Ralph отслеживаются Git.
